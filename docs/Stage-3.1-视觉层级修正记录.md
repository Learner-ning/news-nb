## 0. 一句话结论

Stage 3 的问题不是几何，是**信息层级**：所有来源的叶片共享同一批水平货架，224 张卡片在同一水平带里首尾相接 → 卡片墙。3.1 把叶片改成**每个来源一个独立竖列簇**，并按实际宽度分配横向空间，于是叶片沿枝条散开、来源标签彻底不重叠。**没有回滚 Stage 3，没有重写 `tree-layout.js` 架构，只调了叶片位置、来源节点位置、分类间距、叶片间距、卡片视觉权重和 LOD 策略。**

## 一、问题定位（先量化，再改）

| 用户描述 | 实测指标（Stage 3） |
|---|---|
| 叶片在树冠顶部形成连续"卡片墙" | 同一水平带内最多 **10 片**；顶部 3 档占了 **46%** 的叶片 |
| 来源标签互相重叠 | 来源标签重叠 **27 对** |
| 新闻/来源/分类三层视觉权重混在一起 | 卡片填充 17% + 边框 1.3；枝条主枝仅 7px |
| 枝条变成连接线，卡片成为主体 | 树干 219px / 树冠 2896px 宽 |
| 屏幕上大量文字同时出现 | 默认 fit 落在 LOD 0，224 个标题同时渲染 |

## 二、改动内容（只动允许范围）

### 2.1 叶片排布：共享货架 → 每个来源独立竖列簇

```
Stage 3（旧）：所有来源的叶片按 x 顺序填进同一批水平行
  ────────────────────────────────────  ← 一行里 10 张卡片首尾相接
  ────────────────────────────────────
Stage 3.1（新）：每个来源一个独立竖列簇，沿扇面散开
  ● IT之家 ─┬─ 新闻
            ├─ 新闻
            └─ 新闻
  ● 少数派 ─┬─ 新闻
            └─ 新闻
```

- 簇内**每行一片**（`clusterRowCap: 340`），行间 8px（`leafGapV`）
- 簇间水平 30px / 垂直 22px（`clusterGapX` / `clusterGapY`）
- 簇半径用 **AABB 迭代外推**直到所有簇互不相交（确定性，最多 120 次）

### 2.2 横向份额按「簇实际宽度」分配（关键修复）

第一版按**条目数**分配角带宽度，实测半径被撑到 **5004**（包围盒 9451×5524）——因为簇宽由叶片宽度决定，与条目数无关，窄簇白占宽度、宽簇挤在一起。

改为按簇实际宽度分配后，半径降到 **2841**，包围盒 5737×3356。

### 2.3 来源节点：与第一条新闻拉开距离

来源节点放在**自己簇的基部再向内缩 96px**（`srcLead`），并且**不再落在多条枝的交汇处**。标签跟着节点走，因此天然不重叠。

### 2.4 分类空间

- 分类份额按簇宽分配，每个分类额外留 **90px** 空隙（`catExtraGap`）
- 单分类横向份额上限 **60%**（`maxCatShare`），保证四个分类不互相挤压

### 2.5 卡片视觉权重（枝条成为主体）

| 元素 | Stage 3 | Stage 3.1 |
|---|---|---|
| 叶片填充 | 17% 色 + 白边 | **12% 色 + 52% 同色边** |
| 叶片边框宽度 | 1.3 | **0.9** |
| 叶片圆角 | 10 | **6** |
| 主枝描边 | 7 | **8.5** |
| 分枝描边 | 4 | **4.5** |
| 枝脊描边 | 1.8 | **2.2** |

### 2.6 fit 与 LOD 策略

- **fit 改为默认「整树入镜」**：不再为了标题字号把整树放大到超出视口（那会让第一眼只看到局部）。只有缩到 < 0.16 才退回聚焦，避免"芝麻树"。
- **噪声交给 LOD**：整树入镜时标题只有 3px（不可读）→ 默认进入 **LOD 1**（隐藏标题、只留叶片色条 + 来源/分类标签）；放大到 `scale ≥ 0.5` 自动恢复标题（LOD 0）。LOD 阈值从 `0.42/0.24` 调整为 **`0.5/0.15`**。
- 单分类视图默认就是 **LOD 0**（标题直接可读）。

## 三、为什么视觉噪声降低了（量化）

| 指标 | Stage 3（旧） | Stage 3.1（新） | 说明 |
|---|---|---|---|
| 同一水平带内最多叶片 | **10 片** | **5 片** | 卡片墙的直接度量，减半 |
| 顶部 3 档叶片占比 | **46%** | **14%** | 不再堆在顶部 |
| 叶片纵向分布（下→上 10 档） | 集中顶部 | `25/42/46/31/20/15/13/9/13/10` | 沿枝条铺开 |
| **来源标签重叠对数** | **27** | **0** | 用户最直观的抱怨 |
| 来源簇重叠对数 | — | **0** | 每个来源有独立区域 |
| 叶片重叠对数 | 0 | **0** | 不引入新问题 |
| 默认 LOD | 0（224 标题同时渲染） | **1（结构优先）** | 屏幕文字量大幅下降 |
| 包围盒 / 比例 | 2897×1697（1.71） | 5737×3356（1.71） | 按 3.1 允许放宽比例换取层级 |

**噪声降低的三条主因**：
1. **一行内的卡片数减半**（10 → 5）：不同来源不再共享水平货架，一行只属于一个来源。
2. **来源标签重叠清零**（27 → 0）：来源节点跟着自己的簇走，簇之间用 AABB 迭代保证不相交。
3. **默认不再渲染 224 个标题**：整树入镜时交给 LOD 1，只显示色条与标签 —— 远看是干净的树，放大才出文字。
