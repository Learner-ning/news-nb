## 根因分析（规范 §18）

旧扇形模式（fan）把一级节点（新闻源）全部钉在 `rCat=170` 的固定小圆上，叶片簇则被 AABB 迭代外推到 `2000~2800` 的同一个远端环上。于是视觉上变成：

- 中心一个几乎看不见的小点（16 个来源标签挤在半径 170 的圆上，互相重叠）
- 16 根长直线（平均 1680px，最长 2363px）从中心射向远端
- 远端一堵卡片墙（225 张叶片挤在 2800px 的环上）

另外，枝脊（来源节点 → 叶片簇的连接线）起点用的是平移前的 node 坐标，而叶片簇坐标在 `placeClusters` 里以树干为原点计算，两者坐标系不一致，导致连线末端离自己的叶片簇最远悬空 **477px**。

## 修复方案：可选的 crown 树冠模式

**默认行为不变**：`layoutTree()` 仍使用 fan 扇形模式（与 Stage 3.2 之前完全一致）。首页新闻源树通过 `tree-view.js` 显式传 `mode: "crown"` 激活新模式。

### 树冠模式核心设计

- **6 条粗主枝**（弯曲贝塞尔）从树干顶端向外散开，张角 180°
- **来源节点分布在各自主枝的 40%~96% 处** → 到中心距离天然分散（204~1160px）
- **叶片簇以「左右交替」方式紧贴来源节点两侧**
- **碰撞用局部 AABB 分离**（160 轮迭代）解决，不再整体放大半径

### 关键指标对比（真实数据 225 条 / 16 来源）

> **证据等级 L4（几何复算）**。下表数值来自布局引擎计算输出，**不等于视觉结果**——用户实拍显示视觉上仍为放射状（见 §0.1）。此表仅可作为「几何参数变化」的设计依据，不可作为视觉验收依据。

| 指标 | 旧扇形 | 新树冠（复算） | 变化 |
|---|---|---|---|
| 包围盒面积 | 20.6M px² | 6.8M px² | -67% |
| 来源节点半径范围 | 170~170 px（全部挤在中心） | 204~1160 px（复算分散） | 复算分散 |
| 枝脊长度 (>600px) | 16 条 | 0 条 | 复算消除（**视觉未消除**，见 §0.1） |
| 连线末端悬空 | 最远 477px | 0 px | 复算消除 |
| 几何重叠 | 有 | 复算 0 | 复算消除（**视觉未验证**） |
| 叶片包围盒重叠 | 有 | 复算 0 | 复算消除（**视觉未验证**） |
| 默认 fit 缩放 | 0.226 | 0.325 | +44% |

### 渲染器配合

- 新增 `.limb` CSS：`stroke-width: 11`（明显粗于新闻连接枝 1.8），带生长动画
