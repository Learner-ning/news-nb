为什么 Stage 3.2 的首页会变成「放射图」（实测根因）

  • 一级节点被钉在半径 170 的小圆上。tree-layout.js 里 rCat: 170 是常量，16 个来源节点到 apex 的距离实测只有 170 ~ 204px —— 全部挤在中心。
  • 叶片簇被推到半径 1959 ~ 2798 的同一圈上。placeClusters() 用「AABB 相交 → 整体外推 rIn」的单一环布局：16 个宽簇只能靠不断放大同一个半径来互相让开，于是所有簇都落在远端环上，形成卡片墙。
  • 主枝几乎不可见，连接线又长又直。主枝 apex→节点平均只有 183px（图上就是个点），而来源节点到叶片簇是一条长直线 —— 视觉等价于「从中心射出 16 根细线」。
  • 还有一个坐标系 bug。clusterBase 是在树干平移之前算的，没有跟着 -trunkH 平移，所以每条枝脊的末端都悬空在离自己叶片 477px 的地方（= 树干高度 460 + 叶片半高）。
  • 四条叠加的结果就是 §2 禁止的星爆图：中心小节点 + 16 根长直线 + 远端卡片。

三种候选的共同点

  • 都把来源节点放到主枝上（而不是中心圆上），叶片簇围绕来源节点布置，簇与来源节点的距离由 gapFromNode 控制。
  • 都用少量粗主枝 + 弯曲曲线（A 5 条 / B 3 条 / C 8 条），而不是 16 根直线。
  • 碰撞都用局部 AABB 分离（只推开重叠的那一对），不再整体放大半径 —— 所以包围盒不会无脑增大。
