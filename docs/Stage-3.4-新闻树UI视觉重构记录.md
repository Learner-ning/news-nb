## 1. 一句话结论

首页从「Apple 风格的浅色卡片页」改成了「一棵占满全屏的新闻树」：树冠宽高比对齐 16:9 视口后，
**fit 缩放从 0.277 提升到 0.563（+103%）**，新闻源节点从漂浮白卡片改成**带连接茎的徽标节点**，
分类与主枝一一对应（0 根混分类主枝），DAY / NIGHT 成为两个真正不同的环境。

## 2. 修改了哪些 UI，以及为什么

### 2.1 布局引擎（`public/js/tree-layout.js`）

| 改动 | 为什么 |
|---|---|
| **分类分组**：来源按 `tag` 分组，同分类占据连续的列区间，组间留 `crownBareGroupGap` | §2「不同新闻分类对应不同主枝」。之前列是按宽度全局装箱的，同分类来源被打散成彩虹噪点 |
| 每个分类分配独立的**角度扇区**，扇区宽度按该分类的横向宽度成比例 | 让「x 区间包含 0 的分类」= 「扇区跨越 θ=0 的分类」，两个坐标系的中央一致 —— 中央领导干（θ=0）才能正好承接最内侧的列 |
| **中央分类扇区加宽**（`crownBareCenterBoost = 1.55`） | 中央主枝角度最接近竖直，横向覆盖 = L·sinθ → 角度越小主枝必须越高，树冠被拉得又高又窄。加宽扇区 → 主枝更短更平 |
| 主枝长度改为 `max(min(软上限), farSelf/sinθ)`（硬约束优先） | 主枝必须够得到自己分到的列，否则枝脊被迫斜穿 |
| 分类标签位置改为「同半径小角度试探」而不是「碰撞就无限外推」 | 旧做法把 bbox 高度从 ~2000 推到 2401，fit 缩放从 0.46 掉到 0.28 |
| 节点度量改为**竖式**（`bareNodeH 104`、宽度按真实字号换算） | 横式节点宽度吃满画布 → 树冠过宽；竖式更窄 → 列更密 → 整体缩放更大 |
| 新增 `crownBare*` 专属树干/主枝参数 | 调整首页时不再连带改动已验收的 `crown`（有叶片）几何 |

### 2.2 渲染器（`public/js/tree-view.js`）

- **节点重做**：`连接茎 + 圆形徽标（来源缩写）+ 名称 + 条数`。徽标圆心在节点盒上部，茎从主枝落点连到徽标 —— 这是「节点属于树」的关键（§3）。
- 新增 `sourceAbbr()`：中文取前两字，拉丁取前两词首字母（`Solidot→SO`、`IT之家→IT`）。纯函数、无随机。
- **分类标签**渲染在主枝扇区外侧（`科技·5 / 国内·7 / 影视·1 / 财经·2`）。
- 主枝带 `data-tag`，悬停时只强调当前来源及其所在枝干（§6）。

### 2.3 样式（`public/style.css`）

- 删除 Stage 3.3 的整段 Apple 体系（`--ap-*`），改为 DAY / NIGHT 双环境语义层。
- 主枝加粗到 22px（DAY）/ 18px（NIGHT）：原来 9/8px 在 0.4 缩放下只有 3px，像彩色铁丝而不是枝。
- 顶部改为「左 = NEWS TREE 刊头，右 = 15 SOURCES / 209 STORIES / LAST UPDATED」；刷新与设置按钮**收到下边**（§5）。
- 底部控制条 = 分类 + DAY/NIGHT 两段开关 + 工具。
- 左侧「显示方式」面板压到最低视觉权重（§8 优先级最低）；窄屏只留图标。

### 2.4 顺带修复的两个既存缺陷（与视觉重构无关，但影响可用性）

| 缺陷 | 影响 | 证据 |
|---|---|---|
| `news-store.js` 的 `dominantTag()` 引用未定义变量 `TAG_PRIORITY` | `buildSourceModel()` 抛 `ReferenceError`，首页完全渲染不出来 | 修复前 Node 直接报错 |
| `routes.js` 的 `parseRoute()` 不传参时把路径当成 `"/"` | `app.js` 三处调用都是 `parseRoute()` → 永远返回 main。**直接访问 `/source/:key`、`/detail/:id`、刷新、分享链接、浏览器前进后退全部失效** | 截图实测：`/source/Solidot` 渲染出的是首页；修复后同 URL 正常渲染来源页 |

`parseRoute` 的修复保留了纯函数性质（显式传路径行为不变），并补了回归用例
（`test/source-navigation.test.mjs` 第 22 项）。

## 3. DAY 与 NIGHT 的设计逻辑

两套环境不是换背景色，而是**四个层面同时不同**：

| 层面 | DAY（清晨 / 纸张 / 雾 / 天空 / 现代杂志） | NIGHT（夜空 / 数字生态 / 安静 / 深度） |
|---|---|---|
| 背景 | 顶部薄雾天空 `#c9d9e9` → 纸面 `#f3f0e9` → 底部压深 `#ddd7c9`；三片极淡白色横带模拟晨雾 | 近黑深蓝 `#070b14 → #0a1020 → #04060c`；顶部一层极暗冷光提供纵深 |
| 树干 | 暖棕渐变 `#463a2e → #9d8a6f`，树皮线明显 | 低亮度 `#0d131e → #22303f`，几乎只剩剪影 |
| 主枝 | 分类色 58% 混墨色 `#2a2621`，22px 粗，像墨线 | 分类色 46% 混深蓝 `#16202e`，18px，压暗 |
| 节点 | 饱和徽标 + 深墨字 + 白描边，靠**对比**立住 | 徽标就是**主要光源**，hover 时局部增亮（`drop-shadow` 只在该节点） |

**共同遵守的禁令**（§2 / §4）：不使用散落发光点（`.stars` 层在两套环境下都 `display:none`）、
不使用满屏粒子、不做廉价赛博朋克、不允许整页发光。

## 4. 首页与来源页的层级关系（§7）

| | 首页 `/` | 来源页 `/source/:key` |
|---|---|---|
| 职责 | **探索新闻源** | **浏览该来源新闻** |
| 布局模式 | `crown-bare`（无叶片） | `fan`（保留 Stage 3.2 逻辑，未改） |
| 节点 | 新闻源徽标节点 | 新闻源为根 + 分组分枝 |
| 叶片 | **0**（几何层就不产出） | 15 片真实新闻叶片 |
| 交互 | 悬停预览该来源最新 3 条 → 点击进入来源页 | 悬停叶片看新闻 → 点击进详情 |

两者刻意不做成同一个 UI：首页是「有哪些源」，来源页才是「读新闻」。

## 7. 未验证 / 已知限制

| 项 | 说明 |
|---|---|
| **移动端标签可读性** | 390×844 竖屏下 fit 缩放只有 0.184，名称屏幕字号 ≈3.5px，**必须双指放大才能读**。原因：树冠是横向的（15 个来源 × 2123 宽），竖屏只能按宽度缩放。这是「横向树冠 + 15 个来源」的固有限制，不是渲染缺陷。已做的缓解：竖屏下树冠垂直居中（不再贴底留大片空白）、左侧面板只留图标、隐藏底部提示。**若要在手机上真正可读，需要一个移动端专属的排布（例如竖排分组或按分类分页），本次未做。** |
| 中间距离 LOD | 本次未改 LOD 阈值；首页只有一档（无叶片）。`lod-2` 下节点保持在场已在 CSS 中保证 |
| 无叶片模式的极端来源数 | 几何在 n=1~60 做过扫描（0 重叠 / 0 混分类），但截图只验了真实数据的 n=15。n>30 时 bbox 会超出 4200×3200，未做视觉验证 |
| 来源页叶片字号 | 实测 @1366 约 10px（fan 模式按 §7 未改逻辑）。可读但偏小，未优化 |
| 真机触屏 | 只做了 CDP 的 390×844 视口模拟，**没有真机触屏验证**（pinch 缩放、拖拽手感） |
