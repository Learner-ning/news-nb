## 1. 新布局算法说明

### 1.1 结构（四层，全部来自真实数据）

```
树根(base, 0,0) → 树干(纵向、底粗顶细) → apex(顶端分叉点)
  → 主枝 = 分类，占据一个角度扇区
    → 分枝 = 来源，扇区内的连续角带 + 枝脊
      → 叶片 = 新闻，水平货架（行）排布，挂在分枝上
```

### 1.2 三个关键设计决策（都是被实测逼出来的）

**① 分类按「归一化 x 份额」分扇区，而不是按角度**

最初按角度平均分配扇区，实测包围盒被撑到 8267×4856（树冠半径 4300）。原因：一个扇区的横向可用宽度 = `|sin a1 − sin a0|`，位于扇面边缘的分类（如影视，角度 69°~95°）该值只有 **0.062**，等于几乎没有横向空间，被迫把半径撑大数倍。

改为：先按 `sqrt(条目数)` 权重分配**归一化 x 份额**（上下限 0.06~0.55 防单分类垄断），再用 `asin` 反推角度边界。这样每个分类的横向宽度严格与权重成正比，边缘不再被压扁。

**② 叶片用「水平货架」而不是「同心环」**

同心环在扇面边缘会**纵向重叠**：相邻两环的水平间距只有 `k·r·sinΔ ≈ 39px`，而叶片宽 250px、高 26px —— 39 < 250 且环间距 < 26，必然叠在一起。而且边缘扇区的横向跨度趋近 0。

改为：每个货架（行）独占一个 y 带，行内按 x 顺序排布。货架高度 h 处的树冠半宽 `halfW(h) = k·halfSin·√(R²−h²)`；每个分类在此宽度上占固定比例（即①的 u 区间），因此**分类区域仍然是一个真正的角度扇区**，同时保证零重叠（单元测试第 9 项逐对检测重叠对数为 0）。

**③ 两遍固定点求水平拉伸系数**

`fit` 缩放与包围盒**形状**直接相关：同样的叶片总面积，形状越贴合视口比例，字号越大。因此布局会迭代求解水平拉伸系数 k，使包围盒宽高比收敛到 `targetAspect = 1.72`（阻尼指数 0.75，避免过冲，最多 10 次）。

顺带一提：把比例从 1.78 调到 1.72 后，桌面字号从 6.26px 降到 6.13px，但宽高比从 1.80（贴上限）回到 1.74（有安全余量）。

### 1.3 fit 与 LOD

- **fit（可读性优先）**：`computeFit()` 先算整树入镜的缩放；若低于 `minScale = 0.465`（对应 13px 字号 → 6.05px），**不再继续缩小**，而是保持可读缩放并聚焦树冠中心，由用户拖动/缩放浏览细节。实测默认落在 `fit-all` 模式（整树可见且字号 6.13px）。
- **LOD（语义缩放）**：`lodLevel(scale)` 分三级 —— `scale ≥ 0.42` 完整显示；`0.24 ~ 0.42` 隐藏叶片文字只留形状；`< 0.24` 隐藏叶片、把标签放大到来源节点（`IT之家 · 15`）。切换只改 CSS class，无重排、无随机。

### 1.4 保留的 Stage 1 成果

叶片宽度继续使用 `textWidth()`（CJK 13.5px / 拉丁 7.6px）+ 热度视觉微调（×0.95~1.12），上限 320px；截断继续优先在语义边界（`：，、｜ 空格`）收尾，并先剥离残留 HTML 标签。**未恢复「字符数 × 2.8」旧算法**（单元测试第 10 项静态检查）。
